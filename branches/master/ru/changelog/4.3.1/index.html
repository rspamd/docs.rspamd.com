🐛 Bug Fix ReleaseNovember 22, 2026

Rspamd 4.3.1

Patch Release with Dynamic Configuration, Precise Symbol Profiling, and DKIM, SPF and Scanner Fixes

🛡️ Security

  • A malformed SPF domain no longer turns a DMARC reject into a DNS failure: Sometimes the TXT request for the SPF domain could not be made at all, for example when a label was longer than 63 octets, a character was not valid in a name, or the name was too long. The result was then reported as a temporary DNS failure (R_SPF_DNSFAIL). No DNS server had failed: the resolver refused the request because of the name. The name is the MAIL FROM domain, or HELO when MAIL FROM is empty, so the sender chooses it. When an aligned domain has a temporary SPF failure, DMARC reports DMARC_DNSFAIL instead of applying the policy. With relaxed alignment, which is the default, any subdomain of the From domain is aligned. A message that spoofed a p=reject domain with an envelope sender such as x@<70-octet label>.victim.example therefore got DMARC_DNSFAIL instead of DMARC_POLICY_REJECT. RFC 7208 section 4.3 defines the result for a malformed domain as none, so Rspamd now reports R_SPF_NA, as it already did for an IP literal in HELO. DMARC then sees no SPF pass and no temporary error, and applies the policy
  • One unresolved DKIM signature no longer hides every DKIM result: The DKIM results of a message are published once every signature that has a context also has a result. Three paths gave a signature a context and never a result. The message then had no DKIM symbols at all, not even for signatures that had verified. DMARC, Authentication-Results and other consumers got no DKIM results either:
  • with trusted_only, a signature from a domain not in the map was skipped after its context had been stored. A message with such a signature next to a trusted one lost the trusted result too. This behaviour dates back to 2016;
  • a key request that could not be made, for example for a d= or s= with a label longer than 63 octets. One such header added to a message suppressed R_DKIM_ALLOW, R_DKIM_REJECT, DKIM_TRACE and everything derived from them, with any configuration;
  • a key callback with neither a key nor an error.
  • ClamAV replies without a verdict are failures: Some complete replies are neither stream: OK nor ... FOUND, for example stream: Database reload in progress ERROR. Such a reply left the virus name empty, and the next check on it raised a Lua error in the callback. The failure symbol was never inserted, and the message passed as if it had been scanned. Such a reply is now reported through the failure symbol, with the reply text (#6384)
  • Other scanner errors and unrecognised replies are no longer treated as clean: Several lua_scanners modules treated an error or an unexpected reply as a clean result (#6388):
  • savapi took status codes from anywhere in a line, so a 200 inside a file name counted as clean. Codes are now read from the start of a line, all alert and informational codes are handled, and errors go through the retry and failure path;
  • spamassassin now reads the whole reply. An error reply, or one without X-Spam-Status, is a failure and is not cached;
  • oletools continued after a requery and cached a clean result. A requery now stops the processing, each attempt has its own reply buffer, and the reply is read up to its end marker;
  • fprot, avast, razor, pyzor and dcc set the failure symbol for an unrecognised reply instead of ending silently. sophos matches lines from their start, and a line may span several reads. A temporary file error is a failure in savapi, avast and kaspersky_av;
  • in avast, retransmits counts retries after the first attempt, and its default is 0, so the default is still a single attempt. icap rebuilds its header tables for each attempt
  • The random generator is seeded from the OS first, never from RDRAND alone: libottery's only OS entropy source was opening /dev/urandom. Seeding therefore needed a device node and a free descriptor, in the main process and in every forked worker, and it could read the pool before the kernel CRNG was initialised. RDRAND counted as a strong source. When /dev/urandom could not be opened or read, seeding still succeeded without any message, with a seed made only of RDRAND output. A defective RDRAND, such as one that returns constant output, would then make the generator predictable. Changes (#6393):
  • getrandom() or getentropy() is used when available, and getrandom() waits until the kernel CRNG is seeded. The device is a fallback, or is used when a device or descriptor is configured explicitly;
  • RDRAND is still mixed in, but it no longer counts as strong, so a failure of the OS source fails the seeding;
  • reads interrupted by a signal are retried, the device must be a character device, and a caller-owned descriptor is not closed on an inode mismatch;
  • a failed reinit used to leave the state flagged as initialised. With the init checks compiled out, the next draws returned zero bytes followed by a fixed stream. The flag is now cleared before the init, so a later draw retries the init and aborts if it fails again. Current callers already abort on a failed init
  • Returned random bytes are wiped from the generator state: After a block refill, the byte and integer paths cleared the start of the buffer, which was already zero at that point, instead of the bytes just handed out. Up to 40 bytes of a returned key or nonce, or a whole returned integer, stayed in the generator state until the next refill. This broke libottery's backtracking resistance. The range actually handed out is now cleared (#6393)

🔄 Changed

  • Dynamic scores and actions move to dynconf: Symbol scores, action thresholds and the runtime symbol switch are now dynconf modules (see Added) with C subscribers. The controller's /saveactions and /savesymbols endpoints keep their formats and write through dynconf. The old dynamic configuration code and its JSON map are removed. The primary controller imports the existing dynamic configuration file once and renames it, and the legacy Redis hash is also imported once. The dynamic_conf plugin is now a stub that points to the dynconf Redis backend. Action priorities are stored, so an override.d threshold wins over a dynamic one, which wins over local.d. A null for an action in local.d or override.d disables the action under either spelling of its name. enable_symbol and disable_symbol only work before the symbol cache is initialised, so the cache gains a separate switch to enable a symbol at runtime. Check thresholds that are set both in override.d and from the WebUI: the override.d value now takes effect (#6378)
  • Time intervals in Lua are parsed strictly: lua_util.parse_time_interval ignored trailing text and read a single optional letter as the unit. As a result, "500ms" became 500 minutes, "10x" became 10, and "1 d" became one second. The grammar was also rebuilt on every call, .5s needed a sign, and a number argument raised an error. The whole string is now matched with a grammar that is built once at load. Units are case-insensitive and close to UCL time values: ms, s, m and min, h, d, w and y, plus long forms such as sec, mins, hours, days, weeks and years. Unknown units, trailing text, exponents, compound values and values too large to be exact return nil. Numbers are returned unchanged. For existing configurations, this means:
  • "500ms" and similar values are now milliseconds;
  • "1 d" and "1D" are a day;
  • values such as "10x" or "1month" are rejected.
  • URL hash sets use a random per-process seed: The sender chooses the URLs of a message, and the per-message URL and URL host sets hashed them with a fixed seed. A set of URLs that collide in the table could be prepared once and reused against any installation, which made each insert into the set linear. These sets now use a secret per-process seed, as the headers table already does. url:get_hash() keeps the fixed seed, because Lua code relies on stable values. The order of unsorted task URLs now differs between processes: rules that take the first URL of an unsorted list may see a different URL (#6393)

✅ Added

  • dynconf: runtime overrides of plugin options: The new dynconf framework changes plugin options at runtime without a reload. The lua_dynconf registry owns one settings table per module. A module registers its defaults, its static options, an optional lua_shape schema, and the option paths that may be overridden at runtime. Overrides are validated, merged over the static values and written into the same table in place, so reads remain plain table lookups. Removing an override restores the static value. There are two backends:
  • Redis keeps one hash with a version field. Workers probe the version and fetch the hash only when it changes. Checks run on a periodic timer in each worker, on task arrival after a TTL, or both;
  • the file backend keeps overrides in one JSON file in DBDIR. The controller writes it under a lock with an atomic rename, and workers read it again when its mtime or size changes.
  • Dynamic options in C and Lua plugins: Scalar options of three C modules can now change at runtime (#6378):
  • chartable: threshold and max_word_len;
  • dkim: time_jitter, max_sigs, strict_multiplier and trusted_only;
  • fuzzy_check: retransmits and timeout. Per rule: hits_limit, weight_threshold, skip_unknown, read_only, html_weight, prob_power and prob_bias, plus the hits_limit of each fuzzy_map flag.
  • Dumping and changing overrides: rspamadm configdump --dynamic prints the defaults, static values, dynamic paths and effective values of every registered module, with secrets redacted, and loads file overrides offline. The controller gets the /plugins/dynconf/ endpoints dump, schema, set, reset and reload. set and reset validate against the registry and write through the backend. An update from a backend skips names that a subscriber does not know and reports them, while a write rejects them (#6378)
  • Precise per-scan run times for selected symbols: rspamd_config:register_profiled_symbols() selects symbols and groups whose items are timed precisely on every scan. task:get_symbols_profile([opts]) returns the record as four parallel arrays: names, times, sync_times and flags. The coarse monotonic clock and libev's cached time tick every 1 to 4 ms. The new timings read CLOCK_MONOTONIC in nanoseconds. Details:
  • a virtual symbol is accounted to its parent item. The selection is resolved at the end of init and again after every resort, so dynamically registered symbols are covered. Names that resolve to nothing are reported once at init;
  • the clock is read at the start of a call, when its synchronous part returns, and at finalisation. Items finished by the forced session cleanup are marked as aborted, and all arithmetic saturates;
  • a task allocates timings only when something is selected or the task carries the profile flag. Otherwise no precise clock is read;
  • nil means that the task has no precise timings, and a table with empty arrays means that none of the selected items ran. min_time is evaluated in a counting pass, so no table is built for a task that is not kept.
  • lua_task_profile sampling helper: Exporters of per-symbol run times now have one place that registers the selected symbols and groups and decides, at the end of a scan, whether to keep the record. lua_task_profile.new() validates sample_rate, slow_time, max_slow_rate, groups and symbols. profiler:collect() keeps a scan either as a random sample or because a selected symbol ran for at least slow_time. A token bucket limits slow records per worker, while samples are never limited (#6392)
  • Symbol profiles in ClickHouse (schema version 13): A new profile section of the clickhouse plugin selects symbols and groups and stores their sampled run times. They go into new columns: ProfileReason and Profile.Names, Profile.Times, Profile.SyncTimes and Profile.Flags. Schema version 13 adds them to CREATE TABLE, and migration 12 adds them to existing tables. ClickHouse rejects a whole batch that names an unknown column. A scanner therefore names the new columns in its INSERT only after every upstream has all five of them in system.columns. This is checked at start and then every 60 s. The check looks at the columns rather than the schema version. User extra_columns named ProfileReason or Profile.* are rejected (#6392)
  • DKIM checks From-aligned signatures beyond max_sigs: max_sigs is a positional limit. The plugin examined the first max_sigs DKIM-Signature headers (5 by default) and silently dropped the rest. A new signature is inserted above the existing ones (RFC 6376 section 5.6), so the oldest signatures are the ones cut off, and the author's signature is normally the oldest. On a message that went through several signing hops, the only signature that could give DMARC an aligned pass was the first one lost. The top max_sigs headers are still examined as before. In addition, up to extra_aligned_sigs remaining signatures (2 by default, 0 restores the old behaviour) whose d= is aligned with the From domain are checked. They are taken from the bottom of the message upwards, the strategy that RFC 6376 section 6.1 names. Candidates are found with a cheap look at d= over at most 64 headers, so at most max_sigs + extra_aligned_sigs headers reach the parser and a key lookup. Such a signature is fully parsed and dropped unless the parsed domain is aligned, and also trusted when trusted_only is set. The extra checks therefore cannot get unrelated signatures verified. The new DKIM_SIGS_TRUNCATED symbol (zero score) reports total=N and checked=M whenever some signature headers were not examined. extra_aligned_sigs is a dynamic option, like max_sigs (#6386)
  • RBL: RFC 4648 base32 and ready-made hashes: hash_format = "rbase32" encodes hashed queries as unpadded RFC 4648 base32, while "base32" still means zbase32. With selector_hash = false, selector results are used as they are, for selectors that already return an encoded hash. By default they are still hashed when the rule sets hash (#6381)
  • RBL: per-rule DNS budget: max_dns_requests is an opt-in hard cap on the DNS requests that a rule submits for one message. It counts submitted requests after deduplication, over native checks, selectors, the A/AAAA lookups of resolve_ip and the final queries they produce. Forced requests also obey it. Final queries with the same name are merged before the budget is charged, so a process_script that maps several addresses to one name takes one slot. Before the cut, requests are ordered by a fixed priority: the connecting peer first, then envelope and header data, then content, then selectors. When the cap drops work, a zero-score <SYMBOL>_LIMIT symbol is added, so a truncated check differs from a clean negative answer and from a DNS failure. requests_limit keeps its meaning, and rules without the new options take the same code path as before (#6381)
  • Release base and git distance in the build identity: A build knew only its version and an optional commit hash. The version on master is bumped right after a release, so a nightly could not be told apart from the release it was heading to, nor ordered against another nightly. Builds now record RSPAMD_RELEASE_BASE, the last release tag that the tree descends from. They can also record GIT_DESCRIBE, which is detected in a full git checkout and passed in by the deb and rpm package builds. The describe string is used only when its tag matches the release base. rspamd_version() accepts release_base, dev, distance and describe, and the controller stat reply has the same fields. Development builds print X.Y.Z-dev (<describe>) in --version. RSPAMD_VERSION_NUM now uses at most 8 hex digits of the git ID, because longer hashes overflowed the 64-bit literal (#6379)
  • WebUI: Bootstrap 5.3.9: Bootstrap is updated from 5.3.8 to 5.3.9 (#6380)

🔧 Fixed

  • RPM: the _rspamd user is created on RHEL again: RPM applies ! before >. The condition %if !0%{?fedora} > 43 therefore evaluated as (!0) > 43 on RHEL and (!44) > 43 on Fedora 44, which is false on every system. The %pre scriptlet lost its groupadd and useradd calls. Fresh installs of the 4.3.0 packages on EL8, EL9 and EL10 had no _rspamd user, and the chown in %post failed. The condition is now 0%{?fedora} <= 43, the exact complement of the add_sysuser condition. The scriptlet also runs on upgrade, so upgrading to 4.3.1 creates the missing user (#6385)
  • PRNGs are reseeded in forked workers: Workers are forked from a main process whose PRNGs are already seeded, so all workers drew the same random sequences. math.random was seeded once, when the Lua state was created, and nothing reseeded it after fork. rspamd_random_seed_fast() seeded the fast PRNG only while its state was still zero. Library init in the main process had already set that state, so the call after fork did nothing. The fast PRNG is now always reseeded from libottery. math.random is reseeded in every forked worker and in Lua subprocesses, right after libottery is re-initialised. LuaJIT and Lua 5.1 to 5.3 get one 53-bit seed, and Lua 5.4 and later get two full 64-bit integers. Private generators that worked around the shared sequence now use math.random
  • Phishing: links that display the DMARC-authenticated From domain: Newsletters sent through an ESP show the sender's own domain in the link text and point to the ESP's click tracking. PHISHING therefore fired on mail whose From domain passes DMARC. The plugin already skipped a link whose target is the DMARC-authenticated domain. A link whose displayed domain is that domain now gets PHISHING_OWN_DOMAIN (score 0) instead of PHISHING, so composites can still see the case. Some domains do not get this exemption:
  • domains in the new shared_domains map, which defaults to the freemail list. Any mailbox of a freemail domain passes DMARC for it, so a pass does not show who wrote the message;
  • strict_domains and the exception maps are checked before the exemption, so a strictly protected domain keeps its symbol.
  • Bayes autolearn honours check_balance and min_balance: The balance options of Bayes autolearn are now applied. Legacy key names are normalised on a copy of the merged settings, so successive calls with different balance settings do not affect each other (#6375)
  • Map backends keep their own expiry and are all checked before a reread: Each HTTP backend of a map now stores its own expiry. A map check also stopped at the first backend that reported new data and reread the map at once. A later backend that was due was then read from its cache and kept an expiry in the past. A first URL without ETag and Last-Modified reports a change on every check. Such a map was therefore downloaded from its first URL every few seconds, and its second URL was never requested. All backends are now checked before a single reread. A reread that fails is retried after the next clean check. The expiry timer can fire a moment early, so a backend that expires within a second is treated as due (#6391)
  • HELO address literals in Received headers: The client chooses its HELO, but an address literal in the HELO part of a Received header could be taken as the address of the sending host. Such literals are now ignored when addresses are extracted from Received headers, including with external_relay (#6390)
  • Line breaks before MIME delimiters in lua_mime rewrites: add_text_footer() and multipattern_text_replace() copy parts that they do not rewrite verbatim. RFC 2046 makes the line break before a boundary delimiter part of the delimiter, so the raw content of a part ends without one. The delimiter was therefore glued to the last line of the part. A separate line break is now written before each delimiter, even when the part already ends in one. The end of a standalone body is kept as it is when there is no delimiter (#6394)
  • Flags of repeated URLs: The flags of a repeated URL are meant to be merged into its earlier object. This merge is how 4.3.0 clears the image flag of a URL that is also a link. The URL set could replace its stored object with the new one first, so the lookup returned the new URL itself and the merge did nothing. The earlier object is now looked up before the set is updated, and it stays referenced by the URL lists of the parts it was found in. A URL that an extracted part repeats is kept as an ordinary URL (#6377)
  • HTML_TINY_PIXEL_TRACKER refinements: An image source that the displayed text also spells out is no longer taken as image-only. The flags of the text occurrence merge into the earlier occurrence, so a probe cannot hide its content behind an image whose address it also writes in the text. A zero of any property, inline or in a stylesheet, is now an absolute zero in any unit, including percent and relative units. The image size check shares the selector matching budget with the visibility pass. It matches the selectors of an image tag once and caches the result, so the budget is not spent twice. Once the budget is used up, only inline styles are read. Link icons now share the cascade of image tags (#6377)
  • lua_tcp memory safety and handler queue: An audit of the module found the following problems (#6388):
  • an error callback that closed the connection could free it while the error was still being passed to other handlers, for TLS errors, timeouts, DNS failures and request errors. A request on a session that was being destroyed wrote to freed memory;
  • a Lua handle kept after its connection ended used freed memory. Handles are now weak and report "connection is closed". A sync handle that was garbage-collected while its operation was being resumed, or by code run from the connection cleanup, was freed too early. Text passed as data is now referenced until the connection closes, instead of being taken from its Lua object;
  • an empty write handler, an event with an empty queue or an unexpected head, and a request without a config aborted the worker. A failed connect called registry slot 0 and logged "attempt to call a number value" before the real handlers got the error;
  • a fatal error no longer calls handlers added by the callbacks it runs, and it can no longer loop. shift_callback inside a callback no longer drops the next handler. Nothing is armed on a closed descriptor, and close outside of the callbacks ends the connection;
  • a failed connect counts as one upstream failure, request argument errors release what was acquired, and ports are range-checked
  • lua_tcp sync API, TLS and STARTTLS: Fixes (#6388):
  • sync operations now have a timeout, which was never armed before. A failed connect frees the connection and its descriptor. A coroutine waiting at the end of the task is terminated, the coroutine that yields is the one resumed, and read_once keeps its buffer;
  • decrypted TLS data that is already buffered is now drained, so a reply in one large record no longer stalls;
  • starttls refuses to start while plaintext is pending, honours no_verify, and closes the connection when the handshake setup fails. connect_sync refuses ssl, which it never supported;
  • a STARTTLS failure inside the call raised a Lua error, while a failure a moment later went to the next handler as ssl error. Which one happened depended on timing. starttls now returns true, or false and the error, and raises only on misuse. An immediate failure is passed to the queued handlers when the running callback returns, and the connection is closed then;
  • a TLS connection that failed before its descriptor was duplicated no longer closes descriptor 0
  • lua_smtp calls its completion callback once: When the TCP request failed at once, the callback was called with the error and then called again by sendmail, so callers counted one failure twice (#6388)
  • Task and event loop timers: task:add_timer called its callback on the Lua state that had added the timer. When the timer was added from an asynchronous callback, that state was a pooled thread, which could belong to other code by the time the timer fired. The call broke the suspended coroutine on that thread, and the worker later aborted on a thread pool assertion. Callbacks of task:add_timer and ev_base:add_timer now run on a callback thread taken from the pool. A callback that returns a new interval was not called again: ev_base:add_timer used a one-shot timer that had already stopped, and a task timer was not armed with the new period. Both are now restarted (#6388)
  • Every section of the global config table is imported: rspamd_lua_post_load_config() left each imported section on the Lua stack and looked up the next one relative to the stack top, so it looked into the previous section instead of config. With two sections, one was silently lost or replaced by a nested table of the same name. With three, the lookup indexed nil, and rspamd aborted with an unprotected Lua error (#6382)
  • Lua stack and memory errors in the task, config, util, mempool, map, trie, html, upstream and UCL APIs: An audit of the Lua C API found and fixed the following errors (#6382):
  • task and config: the callbacks of task:add_timer and ev_base:add_timer left two values on the stack every time they fired. task:disable_action returned its argument for an unknown action, and task:set_message read the last argument instead of the second. Symbol registration popped its table copy twice, which worked only when the table was the last argument. Metric processing continued on a string after skipping an entry, and leaked a description to the next symbol. Periodic, finish script and postload callbacks used or left stale values on pooled threads;
  • util and mempool: util.config_from_ucl used the object after releasing it and leaked the config on a parse error. mempool:set_bucket wrote one element past its allocation. The cryptobox hash update read the wrong index for nested tables and texts, and UCL pairs() over an array returned -1 as every key. worker:get_mem_stats pushed one string per jemalloc chunk;
  • maps: map:foreach popped its callback when the callback returned a boolean. It now stops on true and returns the number of elements, as documented. A failing map on_load callback left its error on the stack;
  • tries: callbacks read the result table and the report flag by relative index, which was wrong for a table input and for search_mime, search_rawmsg and search_rawbody. These now always pass the end offset, as documented;
  • other: html tag:get_style() returned the tag itself when the tag had no style block. upstream_list:add_watcher iterated the callback instead of the table of events. The tcp sync write read its table of parts from the wrong index
  • Lua stack errors in scan code: The Redis learn cache left a traceback handler on the main Lua state after each successful check and learn. Lua function atoms in MIME expressions read their numeric result from index 1. Fuzzy learn, unlearn and gen_hashes iterated the last argument as the flags table. Legacy autolearn scripts and classifier conditions read results by absolute index or left them on the stack. Other fixes cover the log pipe loop over rspamd_plugins, the proxy parser script without from, and config Lua loaders that left error messages on the stack (#6382)
  • rspamadm Lua commands: rspamadm lua -P set the path on a string and aborted. A failing Lua command exited with status 0. .exec with several files reused a thread already returned to the pool, and unused threads were never returned. configtest popped a value it did not own and logged a function as the error text (#6382)
  • Lua error messages in tracebacks: Since Lua 5.4.3, luaL_buffinit pushes a placeholder onto the stack, so rspamd_lua_traceback never found the error message. Every Lua error was logged as "unknown error" with only the traceback. The message is now read before the buffer is initialised (#6383)
  • lua_mime compiles with Lua 5.5: Lua 5.5 makes the control variable of a for loop constant. lua_mime assigned to one, so it failed to compile there, and no module that requires it could be loaded. A CI job now builds and tests Rspamd against Lua 5.5 (#6383, #6342)
  • lua_shape keeps false as a field default: A table field declared with a default of false lost it. The default was picked with an and/or chain, so transform returned nil for the field
  • Symbol cache timing decisions: The slow flag is an internal flag, but both reads of it checked the item's type flags, where the same bit means SYMBOL_TYPE_CALLBACK. Every callback item was timed on every task, while the logic that always times an item known to be slow never fired. Both reads now use the internal flags. The timing decision was also tested at start and at finalisation against a flag that all tasks of a worker share. Another task could flag an asynchronous item as slow after it had started without a start time. The item was then measured from the task start, which produced phantom slow-rule notices, bogus counter samples and wrong profile values. The decision is now recorded once, when the item starts
  • RBL symbols are no longer scored twice: A final resolve_ip query whose name matches a query already sent is merged into that query. When the answer had already arrived, the merged part was processed as a new answer and scored the symbol again. The same message could therefore get a different score depending on which reply came first. Its options are now added to the symbol that the answer inserted, and the symbol is not scored again (#6381)
  • rspamc profile times are milliseconds: The profile reply carries milliseconds, but rspamc labelled the values as usec (#6392)

Rspamd 4.3.1 moves dynamic scores and actions to the new dynconf framework, which also lets options of chartable, dkim, fuzzy_check and 41 Lua plugins change at runtime. The release also adds precise per-scan timings for selected symbols, which can be sampled into ClickHouse. A sender could choose a malformed SPF domain that turned a DMARC reject into `DMARC_DNSFAIL`, or add one DKIM signature that hid every DKIM result; both are fixed. Antivirus and other scanner errors no longer pass as clean, and random number generation is hardened. Fresh RHEL installs get the `_rspamd` user again. Before upgrading, review the incompatible changes: an `override.d` action threshold now wins over a dynamic one, Lua time intervals are parsed strictly, and the order of unsorted task URLs differs between processes. Recommended upgrade for all users, and especially for RPM installs on EL8, EL9 and EL10.
